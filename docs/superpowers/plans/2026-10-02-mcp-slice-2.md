# MCP Slice 2 Implementation Plan — Live App Host, In-App Confirmation, Settings

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the running Portmaster app an MCP server over an owner-only local socket, so AI clients read live telemetry instead of a cold sweep and `confirmEach` mutations are approved by a person in a window.

**Architecture:** One protocol, two hosts of the same `ToolExecutor`. The app serves MCP JSON-RPC over a Unix socket (0600) behind a per-launch token; the CLI becomes a router — it relays stdio ⇄ socket when the socket is live and falls back to its existing local executor when it is not. In the proxied path the app is the only authority: it builds the per-call `PermissionGate`, resolves reads from `AppModel`'s published snapshot, and routes mutations through a `ConfirmationBroker` that a window answers. Slice 3's HTTP endpoint becomes "the same server, one more listener."

**Tech Stack:** Swift 5 language mode, SwiftPM (`Core/`), XCTest, `Network` framework (`NWListener`/`NWConnection` over `NWEndpoint.unix`), the pinned `modelcontextprotocol/swift-sdk` (`MCP` product — `Server`, `Client`, `NetworkTransport`, `Transport`), SwiftUI/AppKit for the app side, bash for the e2e script.

**Spec:** `docs/superpowers/specs/2026-10-02-mcp-slice-2-design.md` — the plan argues from the spec; executors read both. Slice 1's spec and plan (`…mcp-support-design.md`, `docs/superpowers/plans/2026-10-02-mcp-support.md`) are already merged and describe the code this extends.

## Global Constraints

- Endpoint file is exactly `~/.portmaster/mcp-endpoint.json`, contents `{socket, token, pid}`, file mode `0600`, inside the existing `0700` directory. Socket path is exactly `~/.portmaster/mcp.sock`, mode `0600`.
- Token: 32 random bytes, hex-encoded, minted fresh on every app launch, compared in constant time, **never** logged and **never** present in any tool output, error string, or Settings row.
- A wrong/absent token, a missing socket, or a dead pid is **"app not available"**: one line on stderr, then the on-demand fallback. Never a transport error surfaced to the client.
- Mutations stay **default-deny** (`off`). In the proxied path the CLI performs no gating at all; the app's gate is the only authority. One authority per call, never two.
- Under `confirmEach`, **every** mutation — `quit_app`, `stop_container`, `stop_project`, `set_preference` — waits for a person: approve → the app performs it, deny or 60 s silence → `isError` with the reason and `outcome: "denied"` audited.
- One audit line per mutation attempt, written by whoever handled the call (app when proxied, CLI in fallback). Reads are never audit-logged.
- `PORTMASTER_MCP=on-demand` forces the on-demand path even when the app is live.
- Existing slice-1 public API keeps its behavior: `ToolExecutor.catalog` (13 tools, 9 read + 4 mutation), `MCPCallContext`, `MCPCatalog.tools()`, `MCPDispatch.call(name:arguments:context:)`, `MCPServerSurface.configure(_:context:)`, `MCPStdioRunner.serve(context:transport:)` / `runMain(context:)`, `LiveMCPCallContext`, `AppLiveness.isPortmasterRunning()`, `AlertSource` / `AlertsSnapshot`, `DataProvider`'s 14 methods.
- Language mode v5, macOS 14, XCTest. The app target gains **no** unit-test target; all new tests live in `Core/Tests/PortmasterMCPTests/`.
- Local-only surface: no network listener on a TCP port, no outbound requests. `~/.portmaster` remains the only path the server or CLI writes.
- `cd Core && swift test` must stay green for all suites, and `xcodebuild -project Portmaster.xcodeproj -scheme Portmaster -configuration Debug build` must stay green.
- No test may signal a real process, write real user preferences, or bind a socket outside a per-test temp directory.

public struct MCPApprovalRequest: Identifiable, Sendable {
    public enum Kind: String, Sendable { case quitApp, stopContainer, stopProject, setPreference }
    public let id: UUID
    public let kind: Kind
    public let summary: String            // "Quit Mail?", "Stop container web", "Change temperatureUnit"

public enum ConfirmationBrokerError: Error, Equatable, Sendable { case windowUnavailable(String) }
public actor ConfirmationBroker {

    public func decide(id: UUID, outcome: ApprovalOutcome)     // answer a pending request
    public var pending: [MCPApprovalRequest] { get }
    public func cancelAll(reason: String)
}

    @Published private(set) var status: MCPHostStatus

    @Published private(set) var clients: [MCPConnectedClient]
    /// Opens/answers the confirmation window. Supplied by Task 8; until then the
    /// controller denies with a clear reason so the broker is never left hanging.
